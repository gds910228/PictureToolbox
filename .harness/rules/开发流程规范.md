# 开发流程规范

> 需求从接收到交付的标准流程（十阶段精简版）。无 CLI，全微信开发者工具。

## 工具链事实

- **无 CLI build/test/lint**：`package.json` 只有 dummy `test`（exit 1）。一切经微信开发者工具。
- 根目录直接打开（flat 布局）。npm 依赖仅 `piexifjs`（EXIF）。

## 流程（对齐 .harness/skills/）

1. **需求分析** `request-analysis`：探上下文 -> 澄清 -> 方案 -> spec.md（用户 review 批准）。
2. **编码实现** `coding-skill`：三层结构落位，硬约束逐条对照；多任务用 subagent-driven-development。
3. **评审** `expert-reviewer` + `code-review`：计划评审 ≤3 轮，编码/测试评审 ≤2 轮，超限升级人工。Critical/Important 必修。
4. **部署验证** `deploy-verify`：参数确认 -> 构建 npm -> 上传云函数 -> 真机预览 -> 日志核对。
5. **完成前验证**（铁律，贯穿全程）：声称完成/修好/通过前，必须跑验证拿证据（见 `verification-before-completion`）。本项目无 CI 兜底，手动验证证据不可省。

## 分支策略

- `main` 是主分支（git user: Aqm）。**不在 main 直接开干**，先建功能分支 / worktree。
- 实现完成 -> 评审通过 -> 验证证据齐全 -> 再合并 / 提 PR。
- rebase 后必须 grep 核验大块交换是否落地（3-way 合并会静默吃 diff）。

## 关键操作（微信开发者工具）

- **npm 依赖变更** -> 工具 -> 构建 npm。
- **部署云函数** -> 右键 `cloudfunctions/<name>/` -> 上传并部署：**云端安装依赖**（云端装 node_modules）。
- **云数据库集合**（`rate_limit` 等）-> 云开发控制台 -> 数据库 **手动创建**（云函数能 add 文档但不能建集合）。
- **预览/真机** -> 预览 -> 扫码。Debug 用 Console + 云开发控制台日志。
- **密钥** -> 云开发控制台 -> 云函数 -> 环境变量（`TENCENTCLOUD_SECRET_ID`/`SECRET_KEY`/`REGION`、`RATE_LIMIT_DAILY`），非任何提交文件。

## 提交规范

- commit message 用中文 + 全角冒号，对齐现有风格：`feat：新增：PDF转图片` / `feat：调优：首页UI…` / `fix：…`。
- 提交前自检：密钥未入库、`.harness/` 在库、`docs/` 与密钥文件未入库。

## Code Review 标准

见 `.harness/skills/code-review/SKILL.md` 静态清单（风格/安全/性能/正确性高频坑）。门禁：Critical（会崩/安全漏洞/数据错）必修，Important（功能缺陷/性能/spec 偏差）继续前必修，Minor 记录待 final review 统一 triage。

## 入库边界

- **入库**：`.harness/`（团队资产）、`pages/`、`utils/`、`cloudfunctions/`（不含 config.json）、`cloudfunctionTemplate/`、`app.*`、`*.example.json`。
- **不入库**：`docs/`、`.claude/`、`config/*.json`（除 example）、`cloudfunctions/*/config.json`、`cloudfunctions/**/local-config.json`、`node_modules/`、`miniprogram_npm/`、`project.private.config.json`。

## 变更管理

每个需求建 `.harness/changes/{类型}-{需求}-{YYYYMMDD}/`，含 `summary.md`（全流程追溯 SoT）+ 各阶段子目录（request_analysis/coding/unit_test/ci_result/deployment）。评审文件版本递增（v1/v2…），旧版永不删。每阶段完成即更新 `summary.md`。

## 红线

- 不跳验证就声称完成（"应该过"/"看着对"不算）。
- 不在 main 直接写码。
- 不漏建云数据库集合就上线限流功能。
- 不把密钥写进任何提交文件。
- 不跳评审 / 不带 unfixed Critical-Important 合并。
