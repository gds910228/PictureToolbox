# 完成前验证（Verification Before Completion）

> 源自 superpowers `verification-before-completion`，按本项目改造。L1 常驻铁律。

## 铁律

```
NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE
```

没在本次消息里跑过验证命令 / 操作，就不能声称"完成 / 修好 / 通过"。违反字面 = 违反精神。

## Gate 函数（声称任何状态前过一遍）

1. **识别**：哪个命令 / 操作能证明这个声称？
2. **跑**：执行完整验证（新鲜的，别用上次结果）。
3. **读**：完整输出 + 退出码 + 失败计数。
4. **确认**：输出是否支持声称？否 -> 报实际状态 + 证据；是 -> 带证据声称。
5. **才能**：下结论。

跳任何一步 = 没验证。

## 本项目验证命令映射表

| 声称 | 必须的验证 | 不算数 |
|---|---|---|
| 云函数部署成功 | 微信开发者工具上传并部署 -> 控制台 / 云函数日志无报错 | "代码写完了" |
| 云函数能跑 | 真机 / 开发者工具调用 -> 返回 success:true（或预期 demo） | "逻辑看着对" |
| 功能正常 | 真机预览走通核心路径 -> Console 无 error | "本地模拟器过了" |
| 限流生效 | 云开发控制台查 rate_limit 文档计数已 inc | "代码里加了 limiter" |
| npm 构建成功 | 工具 -> 构建 npm 提示成功 | "package.json 改了" |
| AI 功能可用 | 真实密钥配置下调用 -> 非 demo 返回 | "demo 模式能出图" |
| 内容安全生效 | 构造违规输入 -> 被拦（确认违规才拦，异常 FAIL_OPEN） | "加了 imgSecCheck 调用" |
| 隐写 / 编码正确 | 用口碑库解出 / 与参考输出比对一致 | "编码器跑通了" |
| bug 修好 | 原症状复现路径 -> 不再触发 | "改了那行" |

## 红旗（出现即停）

- 用 "应该" / "大概" / "看起来"。
- 验证前表达满意（"好了！" / "搞定"）。
- 信 implementer / subagent 的"成功"报告 -> 自己核 VCS diff / 日志。
- 用部分验证外推整体。
- "就这一次不验证"。

## 核心原则

本项目无 CI / 无自动化测试，验证主要靠微信开发者工具 + 真机 + 云控制台手动确认。正因为没自动化兜底，**手动验证证据更不能省**--声称完成却不真机跑过，是本项目最常见的失败模式。

跑命令 / 操作 -> 读输出 / 看日志 -> 才下结论。不可商量。
