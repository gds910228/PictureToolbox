## A. 聊天文件主路径(核心回归,2 用例)

**A1. gifEditor 按指引导入成功**
- 场景:线上"无记录"问题的正路验证
- 操作:文件传输助手聊天 + → 文件 → 选 .gif(显示为文件卡片)→ gifEditor 页点空态卡片 → 会话列表选文件传输助手 → 勾选 .gif
- 预期:选择器能看到该文件;解码进度正常 → 帧列表出现
- 证据:真机截图(帧列表页)

**A2. gifBatch 同路径多选**
- 操作:同一入口在 gifBatch 选 2 个 .gif
- 预期:两个文件卡片出现并逐个解码为"就绪"
- 证据:截图(队列页)

## B. 相册辅助入口(平台行为验证,4 用例)

**B1. 相册选 GIF(多数环境预期转码)**
- 操作:gifEditor 点"从相册试试" → 相册选一张动图
- 预期(转码环境):弹"不是 GIF 文件"modal,文案为相册版本("通常会被微信转成静态图…再勾选…从聊天导入"),非静默、非崩溃
- 预期(直出环境,若存在):正常解码进入帧列表——两分支都算过,记录实际走哪支
- 证据:modal 截图 + Console 无 error

**B2. gifBatch 相册来源失败文案**
- 操作:gifBatch 点"从相册试试" → 选动图(转码环境)
- 预期:文件卡片 status=failed,错误文案"非 GIF:相册图通常被微信转成静态 JPG,请从聊天导入";卡片可移除
- 证据:截图

**B3. 误选静态图归因(评审发现2回归)**
- 操作:gifEditor "从相册试试" → 选一张本来就是静态的 JPG/PNG
- 预期:弹相册版文案("通常会被…"),不把锅绝对甩给微信转码;流程不崩溃
- 证据:截图

**B4. gifBatch 上限边界**
- 操作:先从聊天导入 8 个 .gif → 点"从相册试试"
- 预期:相册只允许再选 1 个;导入第 9 个后 add-btn/source-actions/hint 三者消失,计数 9/9
- 证据:截图(9/9 状态)
